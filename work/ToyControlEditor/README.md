# ShockWave — Toy control

## New: Toys / Shockers pages (2026-10-21)

The top-right button switches pages. Toy functions always appear together, including **Remote {name}**. Generated four-character name suffixes are hidden; internal identifiers stay unchanged. **Shocker control** in the app opens the matching second page with a single-select shocker list.

On Shockers, the two wide-target vertical sliders set **Intensity** (0–100%) and **Duration** (0.3–15 s); moving them sends nothing. **Vibrate** and **Sound** submit once. For Shock, press the **right green ARM circle**, release, then press the **left green SHOCK circle within 3 seconds**. Every shock requires both steps. Holding or dragging across both circles never confirms. Changing values, target, page, input mode or connection cancels confirmation. Values start at zero intensity on app startup and stay in memory. Existing local manual limits and remote owner limits/cooldown/pause/Test mode still apply; 80 capped at 40 becomes 40. Stop cancels pending confirmation and continuous toy input; an already accepted shocker command may finish.

In Unity open **Tools → ShockWave → Toy Control → Add to Avatar**, choose your avatar, explicitly click **Update Toy Control on Avatar**, then upload when ready. No scene or avatar is installed/saved automatically. The new v5 acknowledgement is required before VR shocker input works; the desktop controls work independently. Both touch and either-hand pointing use the same confirmation. Eleven FX layers / 593 local parameters use **zero synced parameter cost**. Live uploaded-avatar, physical output and separate-network response still need testing. Earlier sections below describe the original toy-only version.

The main app owns the accepted curve controller and RAM recordings. **Toy control** is below **Toy panel**. Record/Recording, Play loop, Clear curve, Stop all and Own/Remote/Both use matching button text. Buttons and function rows have uniform four-pixel gaps; destination buttons sit together at the upper right. Hold selected is removed from the panel and menu. With no selected connected function, the waveform/grid is hidden and drawing is ignored. The touch marker uses a green ring and a green bitten disc, matching the supplied reference silhouette. The rounded sections keep transparent margins/gap and separate floating grab strips; connection status stays at the bottom right.

Up to seven functions fit on one page with no paging strip. At eight or more, the strip appears, six functions fit per page, and function seven starts page two. Selection/loops stay with the same function when adding/removing inventory changes paging. The updated **v3** Editor panel adds the seventh row and selected-count feedback. Use **Update Toy Control on Avatar** explicitly to replace this tool's host; the app retains older input names, but an earlier six-row panel cannot display/select the new seventh row until updated.

## Add the finished avatar version

In Unity, select your avatar and open **Tools → ShockWave → Toy Control → Add to Avatar**. Click **Add Toy Control to Avatar**, or **Update Toy Control on Avatar** for an existing installation. Update prepares a new version before replacing only this tool's direct-child host; it recognizes both the current `ShockWaveToyControl` name and the previous name. The old generated assets remain, and the scene-object swap can be undone. Save/build/test or upload yourself. The existing tool and generated-asset folders are retained for compatibility, with VRCFury Full Controller, FX, menu, local parameters, shader and self-only contacts. Existing avatar/controller/menu assets and earlier demos are preserved. No scene is saved or descriptor assignment changed. A humanoid avatar with both hand bones is required. Keep earlier panels hidden while testing.

Keep **ShockWave** running; Shader Lab is no longer needed for this version. Enable OSC in VRChat and open **VRC toy control → Show panel**. **Test mode** defaults off for fresh app settings; existing saved choices are retained. Enable it under Settings → Debug for a preview without output. The badge reports Test mode, connected/live, waiting for ShockWave or unavailable remote routing. Own works with supported local functions; Remote/Both stop this controller's activity and report unavailable until remote transport is implemented. They do not silently send to Own.

## Input and limits

**Touch / Pointer**, beside Play loop, switches input mode immediately in VR or from the matching desktop button. The label shows the current mode. Touch is the startup default. In Pointer mode, aim either hand like a **pistol**, then curl the index into **Thumbs Up** (GestureLeft/Right = 7) to click; hold it while moving to draw. Reopen the index to release. Aim is aligned to the extended index once during installation and follows only the wrist, so every finger gesture keeps the same pointing direction. Each hand has its own ray and XY readings; a drawing stays with the hand that started it. Aim alone never selects or changes output. The mode button can still be touched in Pointer mode, and **Pattern controls → Switch Touch / Pointer** is a menu fallback. Physical finger controls are restored in Touch mode; expression-menu actions work in either mode.

Switching modes cancels unfinished drawing without creating a loop, keeps the Record setting, and requires release before reusing a held click. Leaving the graph during a held pointer cancels that drag; re-entering while held cannot restart it. Grabbing/hiding the board disables pointing. Pointer mode uses two official VRCRaycast components, a generated panel-only collider, self-only custom contacts and green stereo-capable beams/markers, with a three-metre normal-scale range. It requires a PC avatar with both humanoid index-finger bones. It is a custom ShockWave pointer; it does not use VRChat's world-menu laser. Update the avatar once through the Editor tool and upload it yourself to add these components; later mode switches need no upload/restart. Actual headset aim, gesture mapping, collision and comfort still need owner testing.

Each hand's beam and flat circular hover dot appear together only while aimed at the panel; no click is needed to see them. Misses and hits away from the panel hide both visuals. The thin ray target is centered on the board surface, and results live under the panel rather than the moving wrist. Only the invisible contact sender uses the existing front touch-plane offset. Its narrow surface gate rejects floating hits two millimeters from the panel at normal size. The beam has two skinned endpoints attached directly to the live hand origin and native hit, so its tip does not depend on a separately animated length. The dot draws just after the panel with a small depth bias and normal depth testing, staying visible on the surface while remaining hidden behind foreground objects. The larger graph touch ring still appears only while drawing. This avatar-only correction requires **Update Toy Control on Avatar** and another upload; the current EXE remains compatible.

If clicks work but the beam and dot are missing, update with the corrected Editor tool and upload again. The tool now preserves both native ray base prefixes and their derived Hit/Ratio/Distance names through VRCFury's build-time rewriting. Previously the ray prefix could be renamed while the visuals' fields stayed unchanged, leaving beam length at zero and the dot hidden. No EXE update is required.

Select function rows, then touch/draw. Release with Record off holds the last requested value. Record stays enabled until you toggle it off: each fresh touch records and release loops a valid 0.2–60-second recording. Stop, Play, touch cancellation and another function taking control do not turn Record off or restart stopped output. Deselection preserves its loop/held value. Play restarts the selected cached patterns. The legacy Hold input remains accepted for existing panels, while new controls omit it. Recordings are RAM-only and closing the app clears them.

Row touch now requires 200 ms away before another toggle, so a brief fingertip bounce while moving to draw does not deselect it. A live pattern crossing zero keeps its source while the zero command finishes, retaining only the latest next value. Owner Stop/edits and faults still invalidate that source. Unchanged held-value renewals no longer cancel an identical command waiting on the transport.

Starting ShockWave after the VR panel is already shown now connects after two fresh alternating panel pulses, even if VRChat did not resend Visible. An explicit hide still wins. This recovery does not replay pre-existing touches, button presses or patterns; release and use fresh selection/touch.

The default **Updates/toy/sec = 5** is shared by a toy's functions, with a separate shared adapter ceiling of 20 ordinary commands/sec. Six changing functions on four toys were checked with fixtures: no function starved, but a two-motor toy updated each motor roughly every 0.5 seconds in that test. These are app submission intervals, not measured physical response. Higher per-toy settings cannot remove the shared ceiling; limits/rates have not been raised by this fix.

Toy panel **Input** and Stop immediately replace that function's curve value, cancel its unfinished recording/loop, and deselect it. Sibling functions keep their independent state. A fresh graph touch or Play may take control again. Desktop curve controls block a currently held VR touch until release, preventing it from taking the value back. Curve input also updates the corresponding Toy panel Input. Both routes use its saved **Sensitivity** and **Max %**, floor quantization, shared Bluetooth scheduler and Test mode. Graph percentages are requested input; Toy panel Sent/Preview shows the capped/scaled app result, not confirmed motor movement.

The program exclusively owns one OSC listener, using the existing Settings ports and listen host (loopback 9001 input / 9000 feedback by default). It forwards only matching PiCtrl input to the existing OpenShock bridge over private IPC. OpenShock still needs Start bridge and its existing credentials/settings; toy control does not require them. Another OSC receiver owning the port is reported; close Shader Lab and use Reconnect VRC after freeing it. No VRChat config or launch arguments are rewritten.

The local avatar source uses `SzebsToy_*` inputs and `SzebsToy_Rx_*` feedback. Heartbeats alternate every 250 ms in both directions; the app sends its pulse separately before the larger display update. The visible-panel and independent hardware source leases still expire after two seconds. Hide/avatar change/link failure stops only VRC-owned functions; stale renewals cannot restore an owner edit, Stop or reset. Reconnect needs fresh touch/Play; cached clips do not restart automatically. The Windows status distinguishes Panel hidden, Avatar changed and Panel heartbeat interrupted when the link is lost. Desktop-held local input remains independent of avatar visibility. Test mode changes, Bluetooth reset, scan, disconnect and native failures retain existing stopping/no-replay behavior. The user's brief link interruptions have not yet been reproduced in a headset; the pulse changes are mitigation, not confirmed physical evidence.

## Avatar controls and bounds

**Show panel** and **Recall to right hand** place the panel beside your right hand, extending left so your left hand is free to draw. The default gap is 4 cm and forward offset 10 cm, configurable in the installer. It drops after settling; **Follow right hand** keeps it beside the hand until disabled.

Move either hand to either floating strip and make **Fist, pistol / Hand Gun, or Thumbs Up** to grab (VRChat GestureLeft/GestureRight=1, 6, 7). These common gestures work independently of controller-specific finger APIs. You can switch between the three while holding; opening the hand or another unsupported gesture drops it. Both hands can grab either strip, with one holder at a time. At normal size each 1.7 cm-wide, 21 cm-high strip is about 5 cm from the panel section; its receiver is slightly wider. Receivers use self-only HandL/HandR tags. A frozen preparation step selects the hand before unfreezing with rebaked offsets. Graph/buttons accept only FingerIndexL/FingerIndexR, excluding thumb/middle-finger touches. Drawing/buttons and emulation are cleared/suppressed while grabbing, and remain disabled after dropping until 200 ms have elapsed and both hands leave the strips. Recall resets the spawn offset. Hand alignment/grip behavior still needs an actual headset test.

**VRC toy control → Panel size** is a locally saved radial. 50% initially gives the normal 74 cm board width; 0% is 40% of normal (about 30 cm), and 100% is 160% (about 118 cm), excluding the strip gaps. A shared `Panel/Size` child scales Board, strips and every receiver together. It works while dropped because the size child is independent of the frozen placement root. Stop, grabbing and hide/show do not reset Size; VRChat saves it for the avatar across reloads. Calibration retains index-finger XY contacts, axis inversion and menu touch emulation. The avatar has no runtime C#, Udon, PhysBone, particles or sockets.

The v4 avatar has **582** unsynced expression parameters and zero synced cost: 581 unsaved OSC/control/display fields plus one saved local **Size** float (default 0.5). Four grip bools, placement readiness and native ray diagnostics remain Animator-only. Ten FX layers, 30 self-only receivers, two pointer senders and two rays provide independent touch/pointer/grab input and visual visibility. Seven renderers include two eight-vertex/two-bone skinned beams; the other five are the board, strips and dots. The seven-row selection menu puts paging in a submenu to stay within eight controls. Two tiny capsule-cutout meshes render the strips; the graph uses 18 ASCII characters/label, 64 primary samples and up to 16 background waveforms. Existing owner limits, hardware expiry and transport pacing remain.

Only the new requested Editor tool is delivered into the real Unity project. Verification uses a separate scratch project and never opens, switches or saves the real scene or editor state.
