# ShockWave 0.8.1 — fix updates from older versions

This patch fixes the “invalid or duplicate entry” update error when older apps
download the integrated SteamVR release. The 0.8.0 package added root-level files
that their original updater did not recognize. Version 0.8.1 puts the resources
in directories those updaters already accept.

Use **Update → Check for updates → Update**. Existing settings, protected
credentials and mappings remain in their existing location. Normal app closing
and its confirmation still apply. The published 0.8.0 release remains unchanged.

SteamVR now explicitly loads its pinned DLL from `ToyControl/SteamVR`, so an old
root DLL left by a previous installation cannot take precedence. Bindings are
copied from the same directory to the existing stable input location. No pointer,
gesture, smoothing, toy/shocker output, limit or remote protocol is changed.

The launcher supports both the original and compatible layouts. New release
builds check the panel and native DLL/input files, then test complete packages
with unchanged updater implementations from 0.7.0, 0.7.11 and 0.8.0. Native
library diagnostics do not initialize SteamVR or send device commands.

Local full-package checks pass all three original updater pipelines. The actual
published helpers from those versions also successfully install the candidate
in isolated folders, preserving settings sentinels and loading the correct DLL
after upgrade. The integrated panel passes 171 checks with simulated devices.

This is a packaging/update correction. Physical-device behavior and separate-home
network reachability retain the limitations documented for 0.8.0; there is no
TURN relay fallback. Unity projects and the Creator Companion listing are not
modified by this Windows update.
