# SPS body map

The **SPS** tab below **Toy control** uses the requested 1240 × 608 board proportions: toy functions in the left box and a human outline in the right box. SPS remains automatic when an assigned toy is connected and fresh avatar signals arrive. There is no separate SPS Start/Stop or presence switch.

SPS pauses an individual function while a live desktop/avatar or remote Toy control input owns it. A zero within that live input still belongs to that controller. Unrelated functions keep routing. After that input ends, a new SPS contact update can resume the function without toggling All toys or reconnecting; old positive contacts are not replayed. An explicit owner Input/Stop remains authoritative and requires fresh neutral input before SPS rearming.

## Connect and arrange

1. Connect local toys. Shared **Settings → Debug → Test mode** previews requests without actuator commands.
2. Enable OSC in VRChat. ShockWave shares its existing loopback listener, normally 9001, and avatar output endpoint, normally 9000. Another receiver cannot share the input port.
3. Avatar contacts are enabled automatically through VRCFury's Bool `OGB_ENABLED`, sent once per second while the listener is active. Closing/rebinding attempts false. Presence does not select a physical function or renew signal freshness.
4. Turn **Discovery** on. The human outline is replaced by a list of possible plugs and sockets from your avatar's current OSC/query data, including zero-valued contacts. Root/tip and other fields belonging to one zone are grouped. Face tracking, PiCtrl/shock controls, feedback and unrelated parameters are excluded by positive SPS namespace matching. Click **Add** for the zones you want, then turn Discovery off to place their new circles. New signals no longer spawn unsolicited markers; saved zones and their input fields keep updating normally.
5. Names/status appear only on hover. Green circles indicate fresh contact, including while depth waits for calibration; they do not confirm physical output. Hold and drag a circle to place it on the outline. Starting positions use simple name hints; they are presentation coordinates, not measured avatar anatomy. **Lock holes** freezes positions. Click **Locked** to unlock. Lock still permits connections and options.
6. Drag from a toy function card or its colored port onto a circle. The saved line connects that independent motor/function. Several functions can share a hole; a function can connect to several holes. Their requests combine by maximum, not addition.
7. Click a line or its gear for **Connection options**. The gear follows the curve, highlights on hover and gives a click hint. Choose **Depth based** or **Movement based**, enable/disable, scale, dead zone, smoothing, expiry and input range. **Disconnect** removes only that line. Dragging the same pair again opens its existing options. In All toys to all holes mode, manual gears are hidden while those links are paused.
8. Double-click a circle for **Hole options**. Switch other players' SPS sockets, hands/feet/head and SPS plugs, or your SPS sockets, hands/feet and SPS plugs. The three other-player switches start on and the three self switches start off, following the supplied reference. A socket's penetrating plug is controlled by its SPS-plugs switch; a plug's penetration into a socket uses the SPS-sockets switch. Rubbing maps to the corresponding other plug/socket category.
9. **Clear links** removes saved connections while retaining hole positions. **STOP ALL** uses the existing owner stop for all local toys. It does not turn off SPS monitoring; release affected inputs before continuing.

**All toys → all holes** defaults off. Switch it on to route every supported scalar function from the strongest fresh permitted hole/contact, using grouped continuous contacts and calibrated socket depth. Manual lines become grey and inactive; their settings are preserved and restored when switched off. Manual dragging/options/Clear links are paused while it is on. Hole source filters still apply, including self contacts remaining off by default on newly discovered holes. Each toy function's Sensitivity/Max %, Test mode, freshness and Stop remain in force. The mode is saved with the layout; new toys/functions and newly discovered holes join only on fresh input.

Discovery is a session-only view toggle. Existing connections continue to run, and switching views changes no saved routing or positions. Add creates a marker and leaves manual toy assignments empty. An already-added zone says **Added**; list paging/wheel navigation does not edit values. Candidate observations are bounded to 64 zones/16 fields each and expire without refresh after two minutes; avatar/listener reset clears the candidate list, preserving saved layouts. Saved marker positions and wires remain in the existing graph-v1 file.

The read-only query catalog continues when the shared UDP listener is unavailable, including when another app uses port 9001. Recognized query contacts then enter only the discovery catalog, never the routing session. The status remains **OSC UNAVAILABLE** with **Toy output paused · check OSC port**. Free the configured listen port and select **Toy control → Reconnect VRC** to restore routing; cached catalog values are never replayed. The exact input `OGB/Orf/Handjob_Handjob_Right/PenSelfNewTip` is a recognized socket tip, including when zero. Discovery ignores source switches; controlling that socket through your own plug requires **My SPS plugs** in its hole options. Defaults remain unchanged.

Known OGB plug/socket fields retain their existing routing, geometry and source filters. TPS_Internal and plausible additional structured SPS/VFH plug/socket names can appear as **Input setup needed**. Adding an unverified format creates a discovery-only marker that cannot compile into normal or all-holes motor rules; it cannot be connected to a toy until a supported format is available. Query metadata stays separate from routing values. This mode identifies contacts exposed by the local avatar, not private inventories of other players.

**Input setup…** contains optional exact custom input, import and export. Standard generated names, renamed zones and uniqueness suffixes are recognized from actual input. There is no universal anatomical OSC-name list. The app does not edit Unity or VRChat OSC configuration. The list pages six functions at a time and retains unavailable saved functions. Escape, hiding the board, resizing or lost capture cancels an unfinished drag.

**Add received input…** lists up to 64 other finite scalar OSC addresses received locally within the last two minutes, with their latest values. Select one to prefill the custom-input dialog. Adding it creates a zone only; manual mode still needs a toy connection. Automatic all-holes mode includes explicitly added zones on their next fresh input. Custom input ranges can be adjusted in manual connection options. Feedback/presence, invalid values and text are excluded, and avatar/listener reset clears this RAM list. Standard OGB/VFH contacts named Lollipop are recognized without a model database. The reported friend's missing lollipop export has not been captured yet; use this list on the PC that receives its OSC to identify a different parameter format. Other avatars contribute through contacts exported by the local avatar; their own OSC inventories are not automatically received over the network.

Each function card shows its current **input percentage** and colored bar. The smaller **Output** or **Preview** percentage is the last submitted native step after Sensitivity/Max % and quantization; battery is separate. Input can change between motor submissions, so those numbers need not match. Visible input rows refresh approximately every 33 ms; this does not increase Bluetooth's command rate or measure physical response.

## Depth and movement

**All permitted interactions**, the new connection default, responds to the hole's enabled source categories. Continuous contacts take precedence over their binary Close companions. Touch, rubbing and legacy scalar penetration fields provide contact level. On stock socket `PenSelfNewRoot/Tip` or `PenOthersNewRoot/Tip` pairs, the board derives normalized insertion from the one-metre OGB proximity geometry.

For each self/other pair, an outside-tip approach sample learns length `L = tip - root + 0.01` metres when root > 0, tip > root and 0 < tip < 1. Accepted lengths are 0.02…1.01 m. When tip reaches 1, insertion is `clamp(1 - (1 - root) / L, 0, 1)`. No insertion is output before calibration or while the tip is outside. A zero tip or avatar/listener/controller reset clears the learned geometry. Both contacts must be fresh; the earlier contact owns the pair's deadline. Geometry is never persisted. This original implementation adapts the official geometry to OGB's one-metre receiver; VRCFury's internal depth contacts use a different, three-metre radius.

Connect before approach, then withdraw and approach again if the app first sees an already inserted pair. Simulated geometry checks pass; actual avatar contact timing, orientation, scale and multiple-plug behavior still need real VRChat verification.

**Movement based** uses absolute change of the normalized level per second. Input calibration, dead zone/rescaling and scale still apply. The first post-change/reset sample and gaps over 500 ms produce no derivative burst. No new movement for 150 ms means off. Smoothing affects positive requests; zero, invalid or expired input stops immediately.

Imported exact mappings retain their original raw input meaning and all previous settings. Their source switches initially permit all categories to preserve existing Self mappings. Select **All permitted interactions** in their line options to use grouped contacts and socket depth. Individual exact root/tip choices remain proximity inputs. Typed toy Position/Depth settings, continuous OpenShock and remote outputs are unavailable.

## Saving, freshness and ownership

Layout, lock, source filters and lines save atomically in `%LOCALAPPDATA%/SzebsToys/sps-mappings.board.json`, version 1. Existing `sps-mappings.json` version 1 is read as a fallback and left unchanged. Each legacy target becomes a line with pinned exact input. A corrupt board file is retained, reports a warning and falls back to legacy mappings; an explicit replacement also preserves a backup. Metadata discovery does not automatically replace damaged settings. Import validates the complete document and requires fresh input.

Moving a circle or changing Lock only saves presentation. Changing a line/filter requires post-change receipts for changed routes; unrelated routes continue. Neither startup, connection nor detection restores activity.

Freshness defaults to 2000 ms, configurable 250…10000 ms. VRChat UDP sends changes, so a tip can stay at 1 while only its root moves. ShockWave now automatically reads current known SPS contacts through local VRChat OSCQuery while the shared listener is active. Successful snapshots refresh unchanged values; loss of both query and UDP still expires output. Other traffic/heartbeat/presence cannot renew inputs. Optional custom addresses still rely on their actual UDP refresh.

The reader discovers only local VRChat-owned loopback TCP listeners and validates host name, OSC address and configured avatar port. Read-only HTTP GETs use no proxy/redirect, additional OSC socket/server or advertising. One read runs at a time with a 750 ms full deadline, 2 MiB/8192-node bounds, at most 256 recognized routing contacts and up to 256 separate candidate-only messages. It waits 100 ms after a successful frame; failures back off one second. Frames older than 250 ms at delivery are dropped using request-start time; older query values cannot replace newer UDP or cross setup/reset barriers. Avatar changes clear geometry/activity and the discovery catalog. Approach calibration is now monitored before connecting toys. If first seen already inserted, withdraw and approach once. There is no guessed length or implicit cached-value hold.

Routing retains per-function generation leases, owner Sensitivity/Max %, shared Test mode, native floor quantization, latest-value scheduling and priority zero. A lease ends no later than the strongest contributing signal's deadline or two seconds without renewal. Percentages are application request/submission state, not measured motor output.

Fresh neutral immediately requests zero and bypasses smoothing. An existing SPS source remains valid only within its contributing contact deadline, so a quick rise can wait behind its required zero rather than incorrectly entering the owner-Stop gate. Initial neutral never allocates ownership; expired input cannot renew it. Owner override/Stop still invalidate that source and discard pending rises.

The shared toy scheduler now groups up to four ready different toys using serial native calls, avoiding the former pause between each toy. Time inside a slow call counts toward pacing, and a completed zero adds no new shared pause. The 20/sec normal ceiling, per-toy update allowance, intensity limits and freshness/Stop protections remain. This is an app-only change; no avatar update is needed. Physical Bluetooth/motor delay still needs a hardware retest.

Owner Input/graph takeover, Stop, invalid input and invalidated controller leases require fresh neutral across enabled inputs assigned to the affected function before fresh positive input can reclaim it. With several inputs, each must provide a fresh neutral sample; a missing or stale neutral may keep the target blocked. Disconnect/scanning, avatar/controller/listener loss discard SPS-owned activity and accept fresh recovery signals automatically.

Ownership changes carry a monotonic timestamp inside the local controller. A neutral received after that actual change rearms SPS even when it precedes the timer's observation; a neutral before Stop does not. Rearm remains remembered while required zero finishes, and a later ownership change invalidates that rearm. This fixes the change-only release being consumed after Toy control recording/Stop. Record itself remains enabled until explicitly switched off; this preference does not restart output.

The graph is bounded to 64 holes, 16 inputs per hole, 1024 lines and 512 KiB; combinations must compile within 2048 runtime rules. Automatic mode shares contact rules across up to 256 scalar targets; saved exact rules retain their 16-target limit. Live monitoring holds 256 signals. Saved/exported data contains configuration and opaque local function keys, without activity, learned geometry, tokens or native Bluetooth identifiers. Review imported toy assignments on another installation. Fresh app settings default Test mode off; saved explicit settings are retained.

## Verification and references

Run `dotnet run --project tests/sps/Sps.Checks.csproj -c Release` on Windows x64. The 226 checks use fake devices, private loopback sockets, isolated persistence and an offscreen shell/options rendering. They include filtered query/UDP discovery, explicit Add/nonrouting metadata, native list/paging/layout, quick zero/rise ordering, initial-neutral ownership, owner edits/Stop during neutral, recorded-loop/single-release recovery, later Stop ordering, all-holes routing/persistence/new functions, received-input capture and separate live input/native preview/battery rows. They do not load a vendor DLL, launch the real app startup, contact accounts, alter Unity or operate physical toys. A separate earlier production-reader check against running VRChat confirmed discovery and two fresh snapshots without an output controller or settings writes. Actual depth accuracy/contact timing/orientation/scale/multiple plugs, the friend's missing lollipop format and physical output/Stop/timing remain pending. Shared Test mode blocks physical output; hover shows calibration/expiry/Stop status. See [STATUS.md](STATUS.md).
