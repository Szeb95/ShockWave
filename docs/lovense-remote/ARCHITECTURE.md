## Ownership and boundaries

App exit disposes SPS before Toy control's final reset notification; closed SPS pages/readers ignore late reset/start/input callbacks, and reader disposal invalidates pending generations. `LocalToysPage` synchronously disarms its controller, then starts controller/adapter cleanup plus the private `ILocalToyExit` transport-release hook together. Native discovery forwards the hook only to its isolated worker's existing bounded quit/zero/dispose path, avoiding a wait for normal command timeout. Physical stopping remains subject to the existing native limitations.

Settings number fields and dropdowns use `SettingNumberInput` / `SettingChoiceInput`: wheel input is handled and forwarded to the nearest scrollable page, so it cannot alter ports, limits, Bluetooth source/rate or SPS connection values. Explicit clicks, typing and keyboard edits retain the existing handlers and persistence/output rules. This is presentation behavior only; no OSC or controller contract changed.

These paths are guidance, not a request to create empty implementations. Keep the separation of responsibilities if a runtime spike justifies different paths.

Parent heartbeats every 250 ms; pipe closure or 1.5 seconds without a heartbeat revokes further positive output, attempts zero/disposal and exits. Cleanup has a 700-ms bound in the child; the parent bounds ordinary calls at five seconds and forces exit after one second of stalled shutdown. Failure closes the main owner gate. No queued command, native ID, arming or activity survives worker replacement. A hung DLL, device or PC can defeat a physical stop; killing the worker is not proof of stopping the toy. See the implemented private contract in [PROTOCOL.md](PROTOCOL.md).

The worker opens redirected stdin/stdout streams directly with UTF-8 readers/writers. A hidden Windows WinExe has no console, so it must not set `Console.InputEncoding`/`OutputEncoding`: the former crashed the published worker with an invalid handle before native initialization. Fixtures now use the same Windows subsystem; publishing also checks the actual EXE's worker startup in a DLL-free isolated folder. Startup errors distinguish Windows launch failure, premature exit code and readiness timeout without exposing raw native stderr.

## Remote services and zero-budget constraint

Candidate design: free managed signalling to establish WebRTC, direct data channels where possible, and free TURN fallback.

Metered/Open Relay is one candidate. Its advertised Open Relay 20 GB allowance and general TURN 500 MB trial must not be conflated. Verify the actual account plan, regions, quotas, and exhaustion behavior before integration.
