# Windows installer

The installer source now uses **ShockWave** for the app, setup EXE, shortcuts and Windows Apps entry. It retains the existing upgrade identity and saved-data location. Updates check both EXE names before replacing anything, then remove only the former installer-owned names; user-added files remain. A new installer has not been built for this rename; the current portable build is `overlay/dist/shockwave/ShockWave.exe`.

Run `overlay/installer/build-installer.ps1` with PowerShell 7 and the .NET 8 SDK. It produces `overlay/dist/installer/ShockWave-Setup-0.3.0-win-x64.exe`, a checksum, a quick-start guide, and `build-result.json`. Send the **setup EXE**; the payload folders are build artifacts and are not needed by the recipient.

The installer targets Windows 10 1809 or newer / Windows 11 **x64**, installs for the current user without administrator elevation, and registers an uninstaller in Windows Apps and the Start menu. An optional desktop shortcut is available. App startup after setup is opt-in. Updating/uninstalling requires closing the installed copy normally; setup never kills an app/worker. Personal settings/tokens under `%LOCALAPPDATA%\SzebsToys` are retained. Uninstall removes only installer-owned files/shortcuts/registration and preserves user-added files.

The self-contained app includes .NET Windows Desktop 8.0.31, its native runtime files, Node.js 24.21.0 from the official checksum-verified archive, the locked bridge dependencies, production shader files, guides and third-party notices. Fresh default settings have Test mode off and empty hardware UUIDs; updates preserve the user's saved Test mode choice. Developer settings, tokens, native binaries, previews, fixtures and debug files are excluded. Each build uses a new staging directory; a SHA-256 payload manifest records the included files.

The default Bluetooth component fetches the unchanged official BLE v1.2 library from `https://developer.lovense.com/LovenseBLE_Lib.dll`, verifies SHA-256 `74424F9047078D0E02735DC9F7106897161E401DE502D9F18597A3D9D3AFA9CB`, and installs it at the app's existing `native/lovense` lookup path. Download/verification happens **before** changing installed files. A valid existing copy is reused on updates. An initial Bluetooth installation requires Internet access; other components can be selected without Bluetooth. The vendor DLL is not embedded or redistributed in the setup EXE. Lovense's terms/documentation are linked in setup and the guide. Its PE imports are Windows `KERNEL32`, `ole32` and `OLEAUT32`, with no delayed imports; this DLL requires no separate Visual C++ runtime installer.

Complete installation also supplies the existing finished Toy Control editor/shader source under `Avatar-tools/Assets/Editor/SzebsToysToyControl`, excluding its verification fixture. This optional component never launches Unity or modifies a project. The recipient imports it and explicitly uses Add/Update themselves. Unity, VRChat Avatar SDK, VRCFury, avatars and any separate SPS assets remain recipient prerequisites; no external Unity packages or projects are redistributed.

The build script obtains the signed Inno Setup 6.7.3 compiler in the ignored workspace tool cache if needed. Use `-Compiler` for an existing compiler and `-Version` / `-OutputDirectory` to change release metadata/output. Inno Setup's applicable commercial-use terms remain the publisher's responsibility if distribution later becomes commercial. The current friend-sharing setup is unsigned; signing requires the publisher's certificate and is not fabricated by this build.

Run `tests/installer/CheckInstaller.ps1` to test the actual shareable artifact in a unique workspace folder. It refuses to replace an existing registered installation. It verifies every installed file, official download, bundled runtime/bridge loading, app/uninstall shortcuts, Apps registration, in-use guards, update reuse, uninstall and preservation of user files/settings/processes. It never starts the normal app or invokes vendor BLE code. `-InvalidHashInstaller` can supply a separate compile of the same script with an intentionally wrong `VendorSHA256` to verify failure before both a fresh installation and an update. Negative fixtures must remain in ignored `work/installer-checks`, never in release output.

These are installation/loader/fixture checks. They do not establish physical Bluetooth, toy output, recipient-machine compatibility or VRChat headset behavior. No clean Windows VM was available for verification.
