# SPS checks

Run `dotnet run --project tests/sps/Sps.Checks.csproj -c Release` on Windows x64.

The 226 checks use fake connected multi-function devices, memory-only owner preferences, private ephemeral loopback sockets, isolated configuration files and a detached offscreen app shell. They cover signal discovery/types/bounds/generated names, automatic startup and fresh reconnect/avatar/listener recovery, independent edits, feedback rejection, custom calibration, Level/Motion and first-sample isolation, max aggregation, smoothing/zero, receipt barriers, owner Stop/release rearm, Test mode, invalid input, watchdog/strongest-input expiry, quantization/caps, atomic persistence/corruption, UDP late/queued packets and VRCFury presence.

Discovery checks cover filtered plug/socket grouping with zero-valued snapshots, face/shock/feedback/body-only exclusions, unknown-format metadata isolation, full-stem IDs, out-of-order receipts, bounded capacity/field priority, expiry/reclaim, reset/avatar/shutdown safety, explicit Add and duplicate prevention. Unsupported markers round-trip as nonrouting metadata and cannot enter either compiler path. Native checks exercise the mode toggle, Add buttons, hidden-hole/port guards, Added state, pager/wheel selection, live routing preservation and 1040/790 layouts. New markers require Add; prior saved zones still auto-refresh known fields. Captures include `sps-discovery.png` and `sps-discovery-1040.png`/`sps-discovery-790.png`.

Record integration reproduces the consumed single-release bug against the old source and checks recovery, unrelated SPS motors, pre-Stop versus post-Stop release, later Stop invalidation and required zero ordering. All-holes tests cover shared strongest contact, caps/expiry, 256 target capacity, saved preference/manual-line preservation, grey-line interaction disabling and Stop/rearm through real board handlers. Received-input checks cover standard Lollipop discovery, explicit unknown-contact addition, feedback/text/invalid rejection, capacity and reset. Fresh Test-off and preserved saved choices are checked. `sps-all-holes.png` renders the automatic-mode board.

Delayed-zero regressions verify a fresh SPS rise waits behind its required zero without losing the source, initial neutral creates no ownership, retained neutral expires, and owner Input/Stop during neutral requires fresh release before rearming. Live card checks separate requested intensity from capped/quantized native preview, refresh within a 40-ms frame and show current battery independently. `sps-live-rows.png` renders the new percentage/bar; normal/minimum captures retain readable function labels.

Body-map checks cover legacy exact migration, grouped zone discovery, source categories, saved normalized positions/lock/lines, damaged-file preservation, stock root/tip approach calibration, normalized insertion, motion expiry and geometry reset. Actual mouse handlers verify marker movement, moving an active hole without output interruption, Lock, connecting while locked, several functions per hole/several holes per function, targeted Disconnect, Escape/drop cancellation, line clicks, double-click source switches and independent outputs. Native options controls are initialized by showing only those isolated dialogs offscreen. The 1240×608 reference render and normal/minimum shell captures verify the requested box proportions and layout.

Connection-gear checks cover the clickable badge edge, hover/leave affordance, the existing options window, Cancel preserving the saved graph, resizing at 1040/790 pixels and gear suppression while manual lines are paused in all-holes mode. The polished window has a separate title bar, so the fixture selects its actual content TableLayoutPanel and hosts it in an isolated offscreen Form for native capture/layout. The main OverlayForm is never shown and its live startup never runs.

Added query checks cover host/port validation, read-only recognized-contact filtering, fresh unchanged tips, malformed/oversized/failed responses, pre-assignment geometry, newer-UDP precedence, expiry and owner Stop/neutral rearm. UI checks cover hover/leave names, page query/reset barriers, repeated opaque repaint and separate switch cells.

PNG and JSON evidence is in ignored `bin/.../sps-checks/`: `sps-body-reference.png`, `sps-body-1040.png`, `sps-body-790.png`, `sps-line-options.png`, `sps-hole-options.png`, `report.json`.

Quit regressions cover reset/read after query disposal, the actual Form.Close handler order with a pending fake query, cancellation without publishing, and late reset/start/input callbacks leaving SPS closed. Only a native form handle is created; the main form is never shown and its startup handler never runs.

The main Form is never shown: startup does not launch the real bridge or native Bluetooth. The fixture-backed toy page uses simulated inventory; socket feedback goes to a private ephemeral peer. No actual avatar, Unity editor, account/token, vendor DLL or physical toy is used. These are implementation checks. Actual SPS depth calibration, contact timing/orientation/scale/multiple plugs, steady-input refresh and physical output/stopping remain pending. Optional separate live read-only probe: `dotnet run --project tests/sps/Sps.Checks.csproj -c Release -- --read-vrchat`. It discovers local VRChat and reads two fresh snapshots through the production reader, without an output controller or settings writes. `live-query.json` records counts/flags only, without avatar/device identity or contact values. This verifies real input reads; physical routing/depth/output remains pending.
