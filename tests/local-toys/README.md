# Local toy checks

`--intiface-checks` runs nine new fake-phone/software checks: endpoint validation/separate settings/corruption preservation, compressed and split DNS-SD records/malformed replies/goodbye, real loopback fragmented WebSockets and zero-watchdog monitoring, nickname/index/session identity, duplicate-name revocation, automatic connection recovery with Test mode/caps/Stop/no replay, ambiguous-response closure, transient preference exclusion and the actual Bluetooth settings/discovery/save controls. `FakeIntifaceServer` exposes no physical device. Phone Wi-Fi, BLE output, screen locking and physical stop time remain unverified. The full-shell toy checks also render the phone settings at both supported window sizes. The unchanged DPAPI store fixture requires a usable Windows user profile; the restricted execution account may fail that full-suite check.

The exit regression starts a hidden fake worker with a five-second call timeout, stalls its output call and closes the actual page. It verifies synchronous disarming before transport release, completion under 2.5 seconds, worker termination, idempotent cleanup and rejected replay. Native zero/quit is attempted by the existing worker path; this fixture does not establish physical stop timing.

Run on Windows x64 with .NET 8:

```powershell
dotnet run --project tests/local-toys/LocalToys.Checks.csproj -c Release
node --test bridge/bridge.test.mjs
```

The checks link the production discovery/UI sources and use fake or simulated BLE transports. They never load the vendor DLL, start the OpenShock bridge, or activate physical devices. The interface check creates offscreen controls and pumps their event loop; it exercises actual card handlers. Every WinForms thread exception is recorded and fails the check instead of opening a dialog. It exercises repeated source switches/scan/resize, reentrant refresh during card removal, battery updates across sibling cards, per-function versus per-toy Stop, Forget, unknown-function placeholders and retained settings. It saves a preview PNG in its ignored build output for visual inspection.

Mock and offscreen evidence does not establish native ABI compatibility, Bluetooth behavior, physical battery reporting, or redistribution rights. Those remain in `docs/lovense-remote/STATUS.md`.

The suite has 95 checks. Legacy remembered APIs retain flag/manual-disconnect/pause regression coverage, alongside identical-model keys, confirmed remembering, offline/unknown battery restoration, real DPAPI fixture round trips, corruption/write failure, startup, fresh IDs, recovery, forgetting, cancellation/user scans and shutdown. The current page uses automatic-all connections without a checkbox. Preview PNGs remain in ignored output; no real hardware identifiers/settings are used.

`ButtplugChecks.cs` adds twelve production-adapter/controller/actual-card fixtures for connected output during scans, fresh input/priority zero, active-output recovery, stable target-MAC keys across index changes/identical toys, reconnect without replay, pump/rotation ranges, unsupported/missing identity exclusion, battery during scans/five-minute cadence, engine loss/cleanup, explicit Scan pause, Forget quarantine, concurrent save/Forget ordering, Test mode and owner caps. `--buttplug-checks` runs these only. `--engine-check <absolute-intiface-engine.exe>` separately launches the actual pinned engine with **every hardware manager disabled**, verifies v3 handshake/list/scan/pings/canceled submission and bounded exit, then forcibly exits a fixture parent to verify the job kills its engine. No vendor/BLE/account output occurs. Four additional SPS checks cover concurrent-scan routing/expiry and retention of the legacy gate.

`BatteryChecks.cs` adds eight cases using the production adapters and an injected monotonic clock: one read after connection, exact five-minute boundaries, fresh reconnect deadlines/offline cancellation, independent identical-toy schedules shared by multiple motors, scan deferral without stopping discovery, manual refresh restarting the interval, unknown/zero/failed replies without rapid retries, bounded pending timeout/shutdown, and unchanged active Input/owner Stop. `--battery-checks` runs these only. Clock advancement tests the full interval without waiting five real minutes; it does not verify physical sensor responses.

`DiscoveryLatencyChecks.cs` adds nine cases with production-length scan deadlines: four advertised toys connect within a one-second fixture budget; an offline saved toy cannot hold up a found one; late startup toys are discovered after the first batch, with the idle/explicit-pause predicate still enforced; an empty radio retries without the former 30-second gap; duplicate advertisements cannot extend collection; and initial follow-up scans yield connected controls. Missing-toy regressions prove that a 2.8-second delayed Hush advertisement receives a longer uninterrupted search without resetting/reconnecting a healthy toy, fresh manual candidates connect before any absent saved toy can force another scan, and extended searches remain cancellable/paused with no output. `--discovery-checks` runs these cases only. `discovery-first-batch.json` and `discovery-missing-recovery.json` in ignored output record timings/counts with `physical=false`; they are app-coordination evidence only.

Chat 02 adds fake native commands for documented ranges/zero semantics, test-mode previews, arming, independent motor sensitivity/caps/expiry, latest-value coalescing, native rate limiting, priority stop, expired/stale pending input, failure without retry, reconnect without rearming/replay, scanning/shutdown cleanup, idempotent disposal and saved/corrupt preferences. The actual Input/Sensitivity sliders, Max % slider in Options, preview, zero-input and Stop toy handlers run offscreen, with one row per supported function. Fixture thread-stack diagnostics identified a cross-thread post-await layout update; explicit owning-thread marshalling is verified by repeated source switches without ambient context. Fixture-only diagnostics and PNGs stay in ignored test output. `--ui-only` can run the interface checks. No real toy or vendor DLL is used.

`SchedulerChecks.cs` verifies four toys with nine independent functions (including a pump), rolling 20/sec shared bounds, per-toy intervals, fair turns, unchanged suppression, guarded cancellation after transport contention/expiry, Stop before another toy's next normal write, no rearming while zero is submitting, no extra shared pause after zero/slow returns, separate wait/submit measurements, and rate changes preserving limits/original expiry. New fixtures verify three ready toys dispatch together with only one call in flight, and a fifth toy waits beyond the four-toy group both initially and after idle. JSON evidence records software spread/slow-call timings without physical hardware. `--scheduler-checks` runs the eight focused scheduler cases; `--scheduler-comparison` runs ready-group/slow-call comparison only. A real fixture child holds the call gate for a fake battery request and verifies superseded input is never written afterward. The offscreen checks cover pace settings/diagnostics, retention across a source reset and explicit Stop scan remaining stopped across background retry ticks.

Full-shell presentation checks are in `tests/shocker-cards/ToyPanelChecks.cs`: run `dotnet run --project tests/shocker-cards/ShockerCards.Checks.csproj -c Release -- --toys-only`. They use simulated inventory and a detached shell at 1040×760 and 790×590, without showing the main form. They cover eight aligned status panels, truthful simulation/inactive curve/reset states, clickable scan start/stop, the eighth panel resetting to zero Input with retained sensitivity/maxima, Settings ownership, removal of Local toys navigation, matching shocker card geometry and scrolling options. Preview PNGs remain in ignored build output.

The test app is WinExe like production. Worker fault checks launch hidden copies with fake APIs for callback/scalar pipes, repeated power cycles with poisoned process state, crash recovery, heartbeat/parent-pipe loss, hung calls/cleanup and specific startup diagnostics. `CheckPublishedWorker.ps1 -Executable <path>` separately copies the actual package EXE into a unique DLL-free folder and checks hidden worker startup three times. `overlay/build.ps1` invokes that smoke check after publishing; it cannot initialize BLE or activate toys.

`AutomaticReadyChecks.cs` adds seven checks for all saved/new toys connecting regardless of legacy flags with no positive output, empty-radio retry/manual-scan reuse, damaged remembered storage, continuous local input past its legacy duration with caps/Stop/test mode/no replay, native/corrupt-limit closure, idle-only background recovery scans, and cancellation callbacks reading inventory from another thread. The page checks verify separate Input/Sensitivity sliders, full input/zero/scaling/caps/Stop, removal of Connect/Disconnect/Auto-connect/Enable/Seconds/Run, idle preference edits, automatic Cancel/reset retaining sensitivity with zero input, and session pace retention. `--ui-only` runs all five offscreen page checks. This local readiness/held-value mode does not implement OSC/SPS or remote routing and supplies no peer grant.
