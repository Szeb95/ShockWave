# Native shocker-card checks

The suite includes **38 active-output close checks**; run `-- --close-only` for these alone. Actual unshown Form.Close handlers cover idle exit, Cancel preserving card/SPS/input/adapter lifecycle, repeated attempts and confirmed cleanup without a second prompt. Fake native submissions cover Test/simulation exclusions, depth-only settings, positive/zero calls in flight, successful zero and failed-stop uncertainty. Monotonic fixture clocks check accepted/pending/rejected/uncertain windows, multiple devices, Stop, malformed events and expiry after bridge loss. Offscreen warning layout, explicit Close app and default Enter/Escape Cancel are verified; a preview is saved in ignored build output. No main app startup, hardware, real user settings or account calls occur. Separate mock HTTP/history tests in bridge/bridge.test.mjs cover dispatch/outcome events, no-retry/secrets, remaining feedback duration and Stop ordering.

Run `dotnet run --project tests/shocker-cards/ShockerCards.Checks.csproj -c Release`.

The suite includes **64 snap/cooldown rendering checks**; use `-- --snap-only` for these alone. An owned offscreen window receives native size/state/move messages for left/right half-screen dimensions, restore, maximize, short/narrow requests and content z-order changes. Checks cover title/content separation, caption hit testing, painted buttons, correct window state and synchronous repaint. A forced collapsed-caption regression checks recovery on restore and fails against the previous window implementation. Twelve repeated cooldown resize/value/repaint cycles verify that the plain field's empty right area and top/bottom margins are fully painted without hidden arrow fragments. The prior numeric implementation fails this paint regression. This does not reproduce a physical Windows shell drag gesture; startup callbacks are disabled, foreground focus is checked and no hardware/services/user settings are used.

The suite also runs **36 scrollbar/window rendering checks**; use `-- --window-only` for these alone. Managed scrollbar fixtures cover green at rest, delayed hover/leave and native repaint, wheel input, dragging to the bottom, track paging, keyboard input, horizontal scrolling, resizing, page visibility and disposal. An owned main-window fixture checks native sizing flags, synchronous repaint and a straight sidebar boundary through the top inset/title bar, plus the actual Settings scrollbar. This fixture is shown only offscreen with activation disabled and its startup callbacks removed; the running app is never touched. No bridge, OSC listener, native library, physical device or user settings are used.

The suite also runs 19 wheel/settings checks. Use `-- --wheel-only` for these alone. Native wheel messages over number fields, their edit/button children and dropdowns must scroll the parent page without changing values or firing setting changes. The numeric fixture uses the main window's plain field style with hidden spinner buttons. Small repeated deltas, controls outside a scrollable page, real OSC/Bluetooth/cooldown controls and SPS connection options are covered. Numeric increment API, typing and arrow keys remain functional. The real app form is never shown; services and physical devices are not started.

The harness uses fixture configuration files under ignored `bin/`, the actual form save handlers, and offscreen controls. It verifies legacy selection migration, independent top/other ranges, settings/options saves, typed cooldown decimals, retained saved avatar groups/custom OSC addresses after removal of the group field, pending-drag flush, reopening, Apply acknowledgement/stale state, narrow layout, and the requested action-button palette. Except for the isolated rendering fixtures described above, forms are never shown, so bridge and remembered Bluetooth startup do not run. No real token, user settings, account, BLE call, or device command is used.

Separate bridge/share checks: `node --test bridge/bridge.test.mjs bridge/share-limits.test.mjs`. The new share checks use fake HTTP responses; they are not evidence of account permission or physical-device behavior.

Hub checks additionally verify neutral shocker names/power-unknown hover text, preserved name-sync guidance, independent API/hub status, offline/mixed/unknown/stop behavior, equal four-panel sizing in the original row footprint, and readable headings/help icons at 1040- and 790-pixel window widths. Detached status-row renders are saved as `hub-row-1040.png` and `hub-row-790.png` under ignored test output; no form is shown. Use `-- --hub-only` to run only these checks. Name and share regressions retain fake fixture storage. Run all network checks with `node --test bridge/bridge.test.mjs bridge/share-limits.test.mjs bridge/shocker-names.test.mjs bridge/hub-status.test.mjs`.
